# TypeSafe Place 0.2.1

0.2.1 is the first macOS build signed with a Developer ID certificate and notarized by Apple. macOS opens it without the unidentified-developer warning. It also turns on cookie encryption, which waited for signing. The rest of the release is `main` since 0.2.0. Production already serves those changes, because the desktop app is a thin client of the hosted game.

## Signed and notarized macOS app

- **Signing.** `pnpm run desktop:sign` signs the packaged app with a Developer ID Application certificate, the hardened runtime and a secure timestamp (`desktop/sign.js`). With `--notary-profile` it also notarizes, staples the ticket and checks that Gatekeeper accepts the app as "Notarized Developer ID". See `docs/desktop.md`, "Signed macOS release".
- **Entitlements.** The app may use JIT, which V8 needs, and the microphone, which shared voice asks for only after you choose Unmute (`desktop/entitlements.mac.plist`). It gets nothing else: no camera, location, Bluetooth, USB or printing. Chromium's GPU, renderer and plugin helpers keep Chromium's own entitlements.
- **Credentials.** They stay in the keychain. The script names a certificate by name or SHA-1, and reads notarization credentials from a `notarytool` keychain profile. It never takes a password or key.

## Cookie encryption

The `EnableCookieEncryption` fuse is on. Cookies are encrypted with a key in a Keychain item the app creates, and macOS lets later builds signed by the same team use that item without asking. Cookies that 0.2.0 saved unencrypted still read after the update, so you stay signed in. Electron 44 was checked against an unencrypted profile; the readiness ledger has the details.

## Compatibility

- **Versions.** Town checkpoints stay at version 11, and the world protocol is unchanged.
- **Desktop.** The only change to the packaged files is one Studio agent guidance line (`desktop/studio-agent-guide.js`). The new signing script and entitlements file are build tools and are not in the app.
- **Rollback.** Reinstall 0.2.0, then sign in again. A build without cookie encryption cannot read the encrypted store and clears every cookie in it, including those saved before the update. This was checked with Electron 44. Preferences and window state live outside the cookie store and are kept.

## Not claimed

- Windows, Linux, iOS and Unreal distribution.
- Live packaged sign-in, which needs an approved account and an interactive sign-in.
- Human accessibility review, quiet-machine 60 Hz acceptance and production migration acceptance. These remain gated as in 0.2.0.
