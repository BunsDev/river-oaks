# River Oaks desktop execution ledger

Objective: run the existing game in a dedicated, secure desktop application, with live development and measured gameplay performance.

- [x] Electron shell: isolated renderer, native menus, persistent window/preferences, bounded recovery, single instance.
- [x] One-command development: owned Vite lifecycle, hot reload, desktop source restart, clean shutdown.
- [x] Bundled offline app: local assets, no development server required, native macOS package.
- [x] Verify: unit suites, build, Electron gameplay/reload/fullscreen/recovery and performance measurements.
- [x] Leave the development application open for live iteration.

Approach: reuse the Three.js renderer and existing adaptive graphics pipeline. Development uses the existing local shared town; the packaged game uses the existing standalone production mode. No hosted-service credentials are embedded. Optional Python inference remains a separately started development service.

Final verification:
- 536 preview tests, 120 Python tests and 5 desktop unit tests passed.
- Server suite: 67 passed, 27 optional Redis integration tests skipped.
- Production Vite build passed; existing Three.js chunk-size advisory remains.
- Bundled, development and packaged Electron E2E passed: 107/107 requested assets, no page errors.
- Real Adam speech decoded and advanced the audio clock in all three desktop modes.
- Vehicle integration passed for both rides and angel takeoff, following and landing.
- All desktop modes cover shops, conversation, graphics persistence, fullscreen, minimize/restore and forced-crash recovery.
- Bundled sample: 41.3 fps average; 25.0 ms median, 29.2 ms p95 at 1280×768.
- Development sample: 52.5 fps average; 20.4 ms median, 21.4 ms p95 at 1280×768.
- Packaged sample: 42.3 fps average; 24.9 ms median, 29.1 ms p95 at 1280×768.
- These are local workload samples, not a universal 60 fps guarantee. Playwright controls renderer visibility; visibility-triggered suspension also has unit coverage.
