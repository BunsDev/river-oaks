### 8. Rollback rehearsal

`scripts/release/rollback-rehearsal.mjs` runs each order against a v0.2.2 `git archive` and the
candidate. It uses an isolated loopback Redis on port 6497, the real gateway, tickets and
WebSockets, and the fixture identities alice and bob.

Results on `b67597cf`, then rerun against the candidate tree `a42b3835` with the same outcome, on the default revision and on `river-oaks-gardens-3`:

| Order | Result |
| --- | --- |
| `upgrade`: v0.2.2 serves, the candidate takes over | Passes. Positions and chat carry over and everyone can move. It then fails as expected when v0.2.2 takes the state back. |
| straight rollback: the candidate serves, v0.2.2 takes over | **Fails closed.** v0.2.2 logs `town_admission_failed` / `checkpoint_invalid` / `invalid_envelope` and closes every join with 1013. |
| `restore`: back up the room keys under v0.2.2, deploy the candidate, restore the backup, v0.2.2 serves, roll forward again | **Passes** on both revisions. On the candidate: 15 of 15 checks on each revision. |

Why the straight rollback fails:
- 0.3.0 writes checkpoint version 18 (#708, `2ef8eb66`). v0.2.2 accepts only up to version 17.
- The world fingerprint is a digest of the world data, and the world data changed (city kit,
  streetscape).

This matches the documented fail-closed rule: "the bundled district still needs an explicit
migration before replacement" (`docs/world-boundary.md`). No data is corrupted, but the town is
unavailable until an operator acts. The rollback path for 0.3.0 is therefore to restore a room
backup taken before the deploy. That loses anything players changed after the deploy. The
deploy runbook has no step for that backup today.

## Decisions for Val

- **Accept or block on performance.** The candidate is 25–32% over v0.2.2 on CPU p95. #708, the
  resident figures, is one measured cause. Choose one:
  - hold 0.3.0 until the crime lane bounds the figures and the rows are re-measured;
  - accept the regression for 0.3.0 and record it;
  - ship with the figures on a low budget.
- **Pink Jet-Age default.** The candidate ships Pink by default (#831), not Classic. Confirm it,
  or revert #831 for 0.3.0.
- **Pre-deploy room backup.** The only rehearsed rollback to v0.2.2 restores a backup taken
  before the deploy; a plain code rollback fails closed. Add the backup to the deploy steps and
  accept that post-deploy town changes are lost on rollback.
- **Tag, publish and deploy** `v0.3.0` on a qualified commit. The version bump in `package.json`
  is part of the tag step.
- **Desktop.** Electron 45: signing, notarization and real-machine acceptance, per the desktop
  release steps.
- **Human checks:**
  - a VoiceOver and NVDA pass over the street HUD, places, map, dialogs and offices;
  - physical-device acceptance (phone and desktop);
  - production smoke after deploy;
  - the production Gardens precondition, read through an authorized operator path.
- **Accessibility gaps from #863, not fixed:**
  - Gallery v2 (`osm-way-625333006`) is stairs-only, with no step-free route.
