## Design

- **Refusals first.** `desktop/installers.js` calls `checkPackage()` before anything else. `package-check.js` now also reads the binary header (PE, ELF or Mach-O and its machine) and the asar's `package.json` (product name and version), and reports every problem: an unflipped or drifted fuse wire, a binary with no fuse sentinel or of the wrong format or arch, an asar not exactly the staged files, another version. Installers exist only for `win32-x64` and `linux-x64`. A refused build leaves the output folder untouched. One unit test per refusal, on synthetic builds (`desktop/tests/fixtures/synthetic-build.js`).
- **Packaging stays in `package.js`.** Installers start from its output; Windows gets a copy because electron-winstaller writes `Squirrel.exe` into the folder it is given. The only `package.js` change is `desktopName: typesafe-place.desktop` in the staged `package.json`, so Electron's Wayland app ID matches the desktop entry the installers write.
- **Windows.** Squirrel package ID `TypeSafePlace` (`WINDOWS_INSTALL_ID`), so the install lives in `%LocalAppData%\TypeSafePlace`. Files the nuspec template does not name (`LICENSES.chromium.html`, `version`, anything a later Electron adds) are passed as additional files, so the installed copy is the packaged copy. A private copy of the vendor folder gets the host's 7-Zip, and loses its old `signtool.exe` when signing so the Windows SDK's (which supports `/dlib`) is used. `main.js` handles `--squirrel-install|updated|uninstall|obsolete` before anything else: `desktop/squirrel.js` writes or removes the Start menu and desktop shortcuts itself, pointing at `Update.exe --processStart "TypeSafe Place.exe"` with AppUserModelID `works.jev.river-oaks`. Squirrel's own `--createShortcut` would stamp `com.squirrel.TypeSafePlace.TypeSafePlace` and split pinned taskbar buttons from the window. Then `app.exit(0)`, and the lock/window branch is guarded too.
- **Linux.** `.deb` built with `dpkg-deb --root-owner-group`: app in `/usr/lib/typesafe-place`, `/usr/bin/typesafe-place` symlink, desktop entry, hicolor icons 16 to 512, `chrome-sandbox` root-owned 4755, and an AppArmor profile (`userns`, unconfined, attached to `/usr/lib/typesafe-place/typesafe-place`) that `postinst` installs only where `apparmor_parser` accepts the 4.0 ABI, and `postrm` removes. AppImage from appimagetool 1.9.1 with the static type-2 runtime 20251108 (no libfuse2 needed), `AppRun` a symlink to the binary.
- **Pinned downloads.** appimagetool, the AppImage runtime and the Artifact Signing client are pinned by version and SHA-256 in `TOOLS`; a mismatching download is deleted and refused, a cached copy is rehashed before use.
- **Signing.** Pull requests never sign. Every Windows build rehearses signing with an ephemeral self-signed certificate trusted only on its runner, and verifies Setup.exe and every packed PE file with `signtool verify /pa /v`. The rehearsal build is never uploaded. The real `sign-windows` job runs only on a manual dispatch or a `v*` tag, after `signing-config` finds the six repository variables (names only, no secrets: OIDC federation through `azure/login`); otherwise it is skipped with a notice and a step summary.
- **Acceptance on fresh runners.** `desktop/installer-acceptance.js` verifies `SHA256SUMS`, installs, runs the package check on the installed copy and compares every file (bytes, and modes on Linux) with the build manifest `installers.js` wrote, checks shortcuts and the Installed apps entry on Windows (Electron's `shell.readShortcutLink`), launches once with `--proxy-server=127.0.0.1:9` so the app cannot reach production, then uninstalls and checks nothing is left. Linux launches classify the sandbox from the zygote's `/proc` namespaces: its own user namespace, or the setuid helper's PID namespace.
